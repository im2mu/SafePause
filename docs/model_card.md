# 모델 카드: 개인 기준 이상탐지(IsolationForest)

SafePause의 "경량 AI 이상탐지"(제안서 S19·S35)입니다. 룰 필터(시그널 5종)와 함께 씁니다.
제안서 S35의 '거래 시계열 패턴 분류'는 이 프로토타입에서 거래마다 최근 7일·평소 90일 창을 요약한 특징량의
비지도 이상탐지(IsolationForest)로 대신했습니다. 시계열 분류 모델을 학습하지 않았습니다.
기본 설정(조력자에게 '꼭 확인할 때만' 알림)에서는 AI 점수만으로 조력자에게 알리지 않습니다. 당사자가 전체 → 조력자에서
'확인할 때도'와 '모든 것'을 고르면, AI만 걱정한 거래('확인해요')도 그 조력자에게 알립니다(당사자가 정한 범위, S37).

## 1. 개요

| 항목 | 값 |
|---|---|
| 코드 | `safepause/detect/anomaly.py` (`PersonalAnomalyModel`), 결합 `safepause/detect/engine.py` |
| 알고리즘 | scikit-learn `IsolationForest(n_estimators=200, contamination="auto", random_state=seed)` |
| 학습 대상 | **당사자 본인의 과거 거래**만(사람마다 따로 학습). 다른 사람 데이터나 사전 학습 모델 없음 |
| 학습 시점 | 앱: 실제 거래내역은 저장된 거래의 앞 75%(올림, 최소 30건). 걱정되는 거래를 섞은 합성 데이터(샘플)는 마지막 30일 이전 거래(평가와 같은 날짜 경계, 섞은 거래를 배우지 않음). 평가: 사례마다 앞 90일의 정상 거래 |
| 최소 학습량 | 30건(`MIN_TRAIN`). 적으면 학습하지 않고 이상 점수는 늘 0(룰만 사용) |
| 버전 표기 | `iforest-v1-<학습 행 수>` (결합 방식은 `rules-v1+iforest-v1-<n>`) |
| 실행 위치 | 당사자 기기 안: 안드로이드 앱 안 파이썬 엔진(Pyodide, 인터넷 권한 없음). 외부 전송 없음 |
| 결정론 | 같은 seed와 같은 거래 → 같은 점수 |

## 2. 입력 특징량 (11개, `features.FEATURE_NAMES`)

각 거래를 **그 거래 이전의 이력만**으로 계산합니다(누수 방지).

| 특징 | 뜻 |
|---|---|
| `log_amount` | log(1 + 금액) |
| `amount_vs_p95` | 금액 ÷ 같은 거래 방법·방향의 평소 금액 95백분위(분모 하한 1만 원) |
| `hour_sin`, `hour_cos` | 시각(24시간 주기) |
| `is_night` | 심야(23:00~05:59) 여부 |
| `new_counterparty` | 같은 거래 방법에서 처음 보는 상대 |
| `cp_count_7d` | 같은 상대 최근 7일 건수(대상 포함) |
| `cp_sum_7d_ratio` | 같은 상대 7일 합계 ÷ 같은 방법 평소 7일 합계(분모 하한 1만 원) |
| `channel_count_7d_ratio` | 같은 방법 7일 건수 ÷ 평소 7일 건수(1 미만은 1) |
| `new_line` | 통신요금이 청구된 적 없는 회선(통신요금·소액결제) |
| `is_out` | 출금 여부 |

"평소"는 최근 7일을 뺀 과거 90일 구간입니다. 그 구간이 7일보다 짧으면(이력 초기) 평소 값(평소 금액 95백분위 포함)을
알 수 없다고 보고 0으로 두며, 그 시점 거래의 이상 점수도 0으로 둡니다. 학습 때도 이런 초기 거래는 빼되, 빼고 나서 30건이
안 되면 모두 씁니다. 0원 거래는 옮겨진 돈이 없어 평소 값과 건수에 넣지 않고, 음수 금액은 받지 않습니다.

## 3. 점수와 설명

- **점수(0~1)**: 학습 거래들의 이례도(`-score_samples`) 분포에서 대상보다 덜 이례적인 학습 거래의 비율(백분위)입니다.
  1.0이면 "학습한 어떤 평소 거래보다도 이례적"이라는 뜻입니다. 확률이 아닙니다.
- **설명**: 점수가 0.90 이상이면, 학습 분포 대비 표준화 편차(|z|)가 큰 특징 2개까지를 이유로 붙입니다(|z| < 1은 제외,
  "클수록 위험"인 특징의 평소보다 작은 쪽 편차는 제외). 카드에서는 "평소보다 큰 돈이에요", "평소와 다른 시간이에요" 같은
  쉬운 말로 바꿉니다. 학습 때 값이 한 가지뿐이던 연속 특징은 편차를 구할 수 없고 점수에도 쓰이지 않아 이유로 내지 않습니다
  (처음 보는 상대·회선 같은 0/1 사실은 남김). 학습 거래의 시각이 모두 같으면(날짜만 있는 CSV) 평소 시간을 모르므로
  시각 이유를 내지 않습니다.

## 4. 결합 규칙 (앱 기본 = 결합 방식)

| 룰 결과 | 이상 점수 | 등급 |
|---|---|---|
| 고위험 1개 이상 | 무관 | 꼭 확인해요(고위험) |
| 확인해요 | ≥ 0.90 | 꼭 확인해요(고위험) |
| 확인해요 | < 0.90 | 확인해요(주의) |
| 없음, 출금 | ≥ 0.98 | 확인해요(주의) |
| 그 외 | | 없음 |

**모델 단독으로는 고위험(기본 설정의 조력자 알림 대상)을 내지 않습니다.** 오탐으로 조력자 알림이 가서 당사자의 금융 주권을
위축시키지 않도록 한 설계입니다(S38). 당사자가 조력자 알림 등급을 '확인할 때도'로 바꾸고 '무엇을 알릴까요?'를 '모든 것'으로 두면
모델 단독 '확인해요'도 알림 대상입니다(룰 근거가 없는 판단은 시그널 범위를 좁힌 조력자에게는 가지 않음, `guardian/policy.py` `in_signal_scope`).
룰이 '처음인지 알 수 없음'(이력 첫 30일, `newness_unknown`) 때문에 '확인해요'로 낮춘 근거는 이상 점수가 높아도 '꼭 확인해요'로 올리지 않습니다. 0.90·0.98은 명세(SPEC §5)에 정한 값이며 실제 데이터로 보정하지 않았습니다.

## 5. 성능 (합성 데이터 기준, 실제 피해 데이터 검증 아님)

5.1·5.2는 seed 1~20 값입니다. r1~r3에서 룰 기준을 이 seed들의 평가(특히 시나리오 없는 대조군)를 보며 보완했으므로
**표본 안(in-sample) 값**입니다. 룰 보완에 쓰지 않은 seed 21~40(**별도 검증 세트**)의 값은 5.3에 있습니다.

### 5.1 표준 시나리오 (seed 1~20, 표본 안)

출처: `python -m safepause eval --seeds 20 --out docs/eval` → [eval/eval_results.json](eval/eval_results.json), [eval/eval_report.md](eval/eval_report.md).
인물 3종 × seed 20(1~20) = 60사례, 시나리오 5종 × 60 = 300개.

| 방식 | 시나리오 탐지(주의 이상) | 시나리오 탐지(고위험) | 정상 거래 알림률 | 대조군 월평균 알림 |
|---|---|---|---|---|
| 결합(룰+AI) | 100.0% | 100.0% | 1.84% | 0.18건 |
| 룰만 | 100.0% | 100.0% | 1.51% | 0.03건 |
| AI 이상탐지만(비교용) | 100.0% | 54.7% | 9.69% | 3.60건 |

- 시나리오 거래는 룰 기준(SPEC §5)을 넘도록 여유를 두고 만들었으므로 결합·룰의 100%는 설계의 결과이며 실제 탐지율을
  뜻하지 않습니다([dataset_card.md](dataset_card.md) §5). 이 표로는 AI가 룰에 더하는 몫을 알 수 없어 5.2에서 따로 쟀습니다.
- "AI 이상탐지만"의 등급 기준(출금 + ≥0.98 고위험, ≥0.90 주의)은 비교를 위해 정한 값이며 앱은 쓰지 않습니다.
- 이 표에서 AI만 쓰면 시나리오를 넓게 잡지만 정상 거래 알림이 많습니다. 결합 방식에서 AI는 주로 룰의 "확인해요"를
  "꼭 확인해요"로 올리는 데 쓰입니다(예: 거래 단위 고위험 재현율 룰만 55.6% → 결합 79.1%, [eval_report](eval/eval_report.md) §4).
  대신 AI 단독 "확인해요"가 더해져 정상 대조군 월평균 알림이 룰만 0.03건 → 결합 0.18건으로 늘었습니다(대조군 알림 룰만 2건 → 결합 11건, 결합 11건 중 고위험 2건).

### 5.2 경계 변형(subtle) 시나리오: AI가 룰에 더한 몫 (seed 1~20, 표본 안)

시나리오 5종을 룰 기준에 못 미치거나 겨우 닿게 줄인 변형으로 같은 설정(seed 1~20, 60사례, 300개)을 평가했습니다. 변형 정의와 비교 방법은
결과를 보기 전에 SPEC §3·§8 [추가 r4]에 적었고, 결과를 본 뒤 정의·룰·기준값(0.90·0.98 포함)을 바꾸지 않았습니다.
출처: `python -m safepause eval --seeds 20 --intensity subtle --out docs/eval` → [eval/eval_results_subtle.json](eval/eval_results_subtle.json),
[eval/eval_report.md](eval/eval_report.md) 6절.

| 방식 | 시나리오 탐지(주의 이상) | 시나리오 탐지(고위험) | 정상 거래 알림률 | 정상 거래 고위험률 |
|---|---|---|---|---|
| 결합(룰+AI) | 73.3% (220/300) | 63.3% (190/300) | 0.74% (20/2,715건) | 0.33% (9건) |
| 룰만 | 66.0% (198/300) | 20.3% (61/300) | 0.48% (13건) | 0.04% (1건) |
| AI 이상탐지만(비교용) | 92.0% (276/300) | 40.3% (121/300) | 8.69% (236건) | 0.29% (8건) |
| 결합 − 룰만 | +7.3%p | +43.0%p | +0.26%p | +0.29%p |

| 시나리오(각 60사례) | 결합 주의 이상 / 고위험 | 룰만 주의 이상 / 고위험 | AI만 주의 이상 / 고위험 |
|---|---|---|---|
| 심야 반복 이체 | 60 / 60 | 60 / 60 | 60 / 59 |
| 특정 계좌 송금 급증 | 4 / 2 | 2 / 1 | 45 / 2 |
| 통신 소액결제 급증 | 38 / 18 | 18 / 0 | 60 / 32 |
| 신규 가맹점 고액 결제 | 60 / 56 | 60 / 0 | 56 / 8 |
| 단기간 다회선 통신요금 | 58 / 54 | 58 / 0 | 55 / 20 |

- **AI가 새로 찾은 몫은 작습니다.** 룰이 놓친 사례를 AI 점수만으로 잡은 것은 22사례(소액결제 20, 송금 급증 2), 주의 이상 +7.3%p입니다.
- **AI의 주된 기여는 등급 올리기입니다.** 고위험 +43.0%p(129사례)는 모두 룰이 '주의'로 본 사례를 이상 점수 0.90 이상이
  '고위험'으로 올린 것입니다(가맹점 56, 회선 54, 소액결제 18, 송금 급증 1). 결합 규칙상 AI 점수만으로는 고위험이 되지 않습니다.
- 심야 반복 이체는 AI 기여 0%p입니다(룰만으로 60/60 고위험. 그중 57사례는 심야 룰이 아니라 특정 계좌 송금 급증 룰이 고위험을 냄).
- 특정 계좌 송금 급증은 결합도 4/60입니다. AI만 방식은 45/60을 잡지만 정상 거래 알림률이 8.69%입니다.
- 대가: 정상 거래 알림 13 → 20건, 고위험 1 → 9건(2,715건 중). 이 변형도 가정 기반이며 실제 탐지율을 뜻하지 않습니다.

### 5.3 별도 검증 세트 (seed 21~40, 룰 보완에 쓰지 않은 seed)

5.1·5.2와 같은 명령을 seed 21~40(인물 3종 × 20 = 60사례)으로 다시 돌렸습니다. 검증 세트와 지표는 결과를 보기 전에 SPEC §8 [추가 r5]에
적었고, 결과를 본 뒤 룰·기준값(0.90·0.98 포함)·모델·특징량·합성 정의를 바꾸지 않았습니다.
출처: `python -m safepause eval --seeds 20 --seed-start 21 --out docs/eval`(경계 변형은 `--intensity subtle`을 더함) →
[eval/eval_results_holdout.json](eval/eval_results_holdout.json), [eval/eval_results_subtle_holdout.json](eval/eval_results_subtle_holdout.json),
[eval/eval_report.md](eval/eval_report.md) 7절. 칸마다 **seed 1~20(표본 안) → seed 21~40(검증 세트)**.

| 강도 · 방식 | 시나리오 탐지(주의 이상) | 시나리오 탐지(고위험) | 거래 단위 고위험 재현율 | 정상 거래 알림률 | 정상 거래 고위험률 | 대조군 월평균 알림 | 대조군 월평균 고위험 |
|---|---|---|---|---|---|---|---|
| 표준 · 결합(룰+AI) | 100.0% → 100.0% | 100.0% → 100.0% | 79.1% → 78.5% | 1.84% → 1.45% | 1.36% → 1.05% | 0.18 → 0.23건 | 0.03 → 0.12건 |
| 표준 · 룰만 | 100.0% → 100.0% | 100.0% → 100.0% | 55.6% → 55.7% | 1.51% → 1.20% | 0.96% → 0.72% | 0.03 → 0.12건 | 0 → 0건 |
| 표준 · AI 이상탐지만(비교용) | 100.0% → 100.0% | 54.7% → 53.0% | 37.7% → 38.7% | 9.69% → 9.93% | 0.33% → 0.33% | 3.60 → 3.62건 | 0.15 → 0.12건 |
| 경계 변형 · 결합(룰+AI) | 73.3% → 74.3% | 63.3% → 63.0% | 43.0% → 41.7% | 0.74% → 0.80% | 0.33% → 0.54% | 0.18 → 0.23건 | 0.03 → 0.12건 |
| 경계 변형 · 룰만 | 66.0% → 64.7% | 20.3% → 21.0% | 10.2% → 10.5% | 0.48% → 0.58% | 0.04% → 0.07% | 0.03 → 0.12건 | 0 → 0건 |
| 경계 변형 · AI 이상탐지만(비교용) | 92.0% → 94.7% | 40.3% → 38.7% | 37.0% → 35.3% | 8.69% → 9.28% | 0.29% → 0.29% | 3.60 → 3.62건 | 0.15 → 0.12건 |

- **정상 전용 대조군의 알림은 검증 세트에서 더 많습니다.** 결합 방식 1인당 월평균 알림 0.18건(60사례 합계 11건) → 0.23건(14건),
  월평균 고위험 0.03건(2건) → 0.12건(7건). 룰만 방식은 월평균 알림 0.03건(2건) → 0.12건(7건), 고위험 0건 → 0건.
- 검증 세트 대조군의 결합 고위험 7건은 룰이 '주의'로 본 7건(룰만 방식 알림 전부)을 이상 점수 0.90 이상이 '고위험'으로 올린 것입니다.
  기본 설정에서 조력자 알림이 가는 등급이므로, 5.1의 "AI는 주로 룰의 '확인해요'를 '꼭 확인해요'로 올린다"는 성질이 정상 거래에서는
  조력자 오탐 알림으로 이어진다는 뜻입니다(표본 안에서도 2건 → 2건으로 같은 모양).
- 경계 변형에서 결합 − 룰만 차이(AI가 더한 몫)는 주의 이상 +7.3%p → +9.7%p, 고위험 +43.0%p → +42.0%p로 비슷했고,
  정상 거래 고위험률 차이는 +0.29%p → +0.47%p(룰만 2건 → 결합 15건)였습니다.
- 같은 합성 생성기에서 seed만 바꾼 데이터입니다. 룰 보완에 쓰지 않은 표본이라는 뜻일 뿐 다른 분포·실제 거래로 검증한 것이 아니며,
  60사례 두 묶음의 차이에는 표본 변동이 섞여 있습니다.

### 5.4 단순 규칙 대비 점검: AI가 등급을 올리는 몫은 판별력이 아니다 (seed 21~40)

결합 방식의 '룰 주의 + 점수 0.90 이상 → 고위험' 상향은 룰이 '주의'로 본 거래를 거의 모두 올립니다. 그래서 AI 없이 **'룰 주의 이상을 모두 고위험으로 본다'**는 단순 규칙과 성적이 거의 같습니다. 아래 표는 검증 세트 JSON의 룰만 방식 '주의 이상' 값과 결합 방식 '고위험' 값을 나란히 놓은 것입니다(새 실행 없음).

| 비교 (검증 세트) | 단순 규칙 = 룰만 '주의' 이상 | 결합 방식 '고위험' |
|---|---|---|
| 표준: 거래별 재현율 | 79.2% (1,306/1,650) | 78.5% (1,295/1,650) |
| 표준: 주입 사례 정상 거래 비율 | 1.20% (33/2,759) | 1.05% (29/2,759) |
| 경계 변형: 시나리오 탐지율 | 64.7% (194/300) | 63.0% (189/300) |
| 경계 변형: 주입 사례 정상 거래 비율 | 0.58% (16/2,759) | 0.54% (15/2,759) |
| 대조군 1인당 월평균 | 0.12건 (7건) | 0.12건 (7건) |

- 따라서 앞 절의 '룰만 → 결합 고위험 +42%p'는 AI의 판별력이라기보다 **룰 '주의'를 일괄로 한 단계 올린 효과**에 가깝습니다.
- AI만의 몫은 **룰이 못 본 출금에 '주의' 카드를 먼저 띄우는 경로**(룰 없음 + 출금 + 점수 0.98 이상)입니다. 표준 검증 세트에서 거래별 주의 이상 재현율 79.2% → 83.5%(1,306 → 1,378건), 첫 카드 전 평균 유출 95,771원 → 67,031원입니다. 대가로 대조군 월평균 알림 0.12 → 0.23건입니다.
- 개선 과제: 룰 발동 조건과 겹치는 특징(새 상대·새 회선 등)을 뺀 모델이나 거래 순서를 보는 모델로, 이 단순 규칙보다 나은지 새 seed로 검증.

## 6. 한계

- **합성 데이터로만 평가했습니다.** 합성 데이터는 가정 기반이며 공개 통계로 보정하지 않았습니다([dataset_card.md](dataset_card.md)).
  실제 당사자의 거래 패턴, 실제 착취 수법에서의 성능은 모릅니다.
- 학습 거래가 적으면(30건 미만) 모델을 쓰지 않습니다. 초기 이력(평소 기준 7일 미만)에서는 점수가 0입니다.
- 점수는 본인 학습 분포 안의 상대 순위입니다. 학습 기간에 이미 착취가 섞여 있으면 그것을 "평소"로 배웁니다.
- 생활이 바뀌면(이사·취업·새 휴대폰) 평소와 다른 정상 거래가 늘어 알림이 많아질 수 있습니다. 앱은 데이터가 바뀔 때마다
  다시 학습합니다(실제 거래내역은 앞 75%). 실제 거래내역의 앞 75% 안에 착취가 있었다면 그것을 평소로 배웁니다.
- 상대 판별은 계좌·가맹점 식별값(없으면 이름)에 기대므로, 가져온 CSV에 식별값이 없으면 같은 이름을 같은 상대로 봅니다.
  식별값의 공백·하이픈·점은 무시하고, 가린 계좌(*)는 조력자 알림 정책과 같은 규칙(같은 길이, 보이는 숫자 4개 이상이 모두
  같음)으로 같은 상대로 봅니다. 그래서 가린 자리만 다른 서로 다른 계좌는 같은 상대로 볼 수 있습니다.
- 설명(z 편차)은 모델 내부 판단의 근사이며 인과를 뜻하지 않습니다.

## 7. 쓰임새와 쓰면 안 되는 곳

- 쓰임새: 당사자가 돈을 보내기 전에 스스로 한 번 더 생각하도록 돕는 안내(안전 정지), 당사자가 정한 조력자 알림의 보조 근거.
- 쓰면 안 되는 곳: 거래 차단, 신용 평가, 당사자 동의 없는 감시, 당사자 결정을 대신하는 판단.
