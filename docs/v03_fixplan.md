# SafePause v0.3 수정 계획 (적대적 검증 145건 반영, 2026-10-03)

검증 결과 원본은 `scratchpad/w3/findings_all.json`이다. 담당별 목록은 `scratchpad/w3/assign_<담당>.json`에 있다.
이 문서의 결정과 계약이 담당별 목록의 제안(fix)보다 우선한다. 결정과 다르게 고쳐야 하면 보고에 이유를 적는다.

## 1. 결정

### A. 돈 보내기 의미 정리 (claims C1·C3, FN-02, RF-3·6·7, J4, C13)

- `check`는 거래를 저장하지 않는다(지금과 같음).
- **걱정 없음(카드 없음)이면 화면이 decide를 부르지 않는다.** 본인이 고르지 않은 결정은 기록하지 않는다.
  - 결과는 "걱정되는 점이 없어요."다.
  - 계좌 이체일 때만 [내 은행 앱 열기]를 보인다.
- **그래도 보낼래요(send)**: 지금처럼 확인한 거래를 내 거래에 적는다(반복 송금 탐지에 필요). 거래 이름은 '보내기 전 확인'이다. 단, 다음을 지킨다.
  - **돈 흐름 분석(insights)의 나간 돈·건수·차트에서는 확인한 거래(live id)를 뺀다.** 실제로 보냈는지 모르기 때문이다.
  - 확인한 거래의 시각
    - 저장된 실제 거래(live 아님)의 마지막 시각이 지금부터 45일 안이면 '지금'을 쓴다(실사용).
    - 그보다 오래됐으면(합성·옛 데이터) 마지막 실제 거래 날짜에 고른 시각을 붙인다(데모).
    - 여러 번 확인해도 날짜를 하루씩 미래로 밀지 않는다.
  - 내 거래 시트에서 확인한 거래는 [이 확인 기록 지우기]로 지울 수 있다(새 API 3.6).
- **결과 화면**
  - 계좌 이체가 아닌 방법(가게·휴대폰 결제 등)이면 [내 은행 앱 열기]와 필수 문장을 보이지 않는다. 결과 글만 보인다.
- **조력자에게 물어볼래요(ask_helper)**
  - "이영희에게 알려 드릴게요" 같은 **보낸 척하는 약속을 쓰지 않는다.**
  - 결과 제목은 "조력자에게 물어봐요", 글은 "아래 버튼으로 이영희에게 문자를 보내 물어봐요."처럼 쓴다.
  - 주 버튼 [문자로 물어보기]·[메일로 물어보기]를 누르면 알림 보내기로 간다. 고른 조력자를 미리 체크하고, 확인 내용을 글에 미리 채운다.
  - 파이썬의 자동 기록(kind auto)은 남긴다. 다만 화면은 이것을 '보낸 알림'이 아니라 **'적어 둔 기록'** 으로 구분해 보인다(보낸 알림 탭 안 별도 묶음 또는 배지 "적어 둠, 아직 안 보냄").
  - 파이썬 문구에서 '알려 드릴게요/알렸어요'처럼 보냈다는 뜻을 없앤다.
  - 당사자 화면에 보이는 자동 기록 글에서 "결정은 본인이 해요."를 뺀다(사용자 금지 문구와 같은 뜻).
- DELIVERY_NOTE 같은 파이썬 문구에는 '이 기기'를 넣지 않는다. 장소 말은 화면이 deviceWord()로 붙인다.
- C13: "보내기 전에 받는 사람과 금액을 AI가 한 번 더 살펴봐요"는 조건을 붙인다. 30건 미만이면 약속(규칙)으로만 보고, 동의가 꺼져 있으면 살펴보지 않는다.

### B. 받는 사람 (RF-1·5, FN-06, FE-07, J12, BE-4·5)

- `POST /api/notify/suggest`는 선택 칸 `pending`(PendingIn 모양: to, amount, channel, to_id, time)을 받는다. 저장하지 않은 확인 거래도 이해충돌·등급을 판단한다.
  - 물어볼래요 → 알림 보내기 흐름은 pending을 넘긴다.
  - 돈 받는 조력자는 경고 + 체크 해제 + 확인 시트다.
- 이해충돌은 **나간 돈(direction out)의 받는 사람**만 본다. 들어온 돈을 보낸 조력자는 충돌이 아니다(BE-4).
- 알릴 조력자가 모두 충돌이면 policy처럼 상담하는 곳을 추천한다(BE-5).
- **상담하는 곳은 자동으로 체크하지 않는다**('추천' 배지만 단다). 예외는 `?to=counselors`로 들어왔을 때이며, 이때는 추천받은 상담하는 곳만 체크한다.
- **조력자와 상담하는 곳은 한 문자·메일에 묶지 않는다.** 3단계 '어떻게 보낼까요'는 받는 사람 무리(조력자 / 상담하는 곳)마다 따로 앱을 연다.
  - 예: [조력자 2명에게 문자 보내기]와 [상담하는 곳에 전화하기]
  - 상담하는 곳은 번호가 있으면 전화(다이얼 화면)가 기본이다. 문자·메일은 본인이 고를 때만 쓴다.
- 받는 사람은 최대 10명이다. 10명을 고르면 나머지 체크 칸을 비활성으로 하고 안내를 보인다. 말없이 자르지 않는다.
- 상담하는 곳에 보내는 글에는 보내는 사람과 요청을 넣는다(J12).
  - 예: "[SafePause] {내 이름}입니다. 걱정되는 거래가 있어 상담을 받고 싶어요. …"
  - '내 이름'(선택)은 알림 보내기 화면에서 적고 localStorage `safepause.myName`에 저장한다. 모두 지우기에서 지운다.

### C. 오탐 바로잡기 '내가 한 거예요' (J1, AUG-01)

- 새 저장 파일 `reviews.json`: `[{txn_id, status: "ok", created_at}]`
  - 모두 지우기와 거래 통째 교체 때 비운다. 이어 붙이기 때는 유지한다.
- API
  - `POST /api/reviews {txn_id}` → `{ok, count}`. 거래 살펴보기 동의가 필요하고, 없는 거래는 404다.
  - `POST /api/reviews/remove {txn_id}`
- transactions·cards·flags 항목에 `reviewed: bool`을 더한다.
- **탐지 등급·평가 수치는 바꾸지 않는다.** 바뀌는 것은 표시와 일부 집계뿐이다.
  - 알림 탭 '걱정되는 거래' 수와 홈의 '꼭 확인할 거래 N건'은 내가 확인한 것을 빼고 센다. 뺀 건수는 함께 보인다(예: "내가 확인한 3건은 뺐어요").
  - 상담 안내 기준(30일 3번)과 suggest의 counseling_due도 내가 확인한 것을 빼고 센다.
  - 카드·거래 줄에는 '내가 확인함' 배지를 단다. [확인 취소]로 되돌릴 수 있다.

### D. AI가 한 일 보이기 (J2·J3)

- `_item`에 `ai` 칸을 더한다: `{"fitted": bool, "percentile": 0~100 또는 null(평소보다 다른 정도, 클수록 다름), "top_feature": "쉬운 말 한 줄" 또는 null, "only_ai": bool}`
  - 기존 explain의 '평균과 가장 다른 특징 1가지' 함수를 재사용한다. 모델 기여도라고 쓰지 않는다.
- 거래 시트와 알림 카드 자세히에 '왜 걱정되나요' 두 갈래를 보인다.
  - **약속(규칙)으로 본 것**: 명사형 신호
  - **AI가 본 것**: 예) "평소 내 거래와 다른 정도: 상위 3%" + 그 특징 한 줄
  - 모델이 없으면(30건 미만) "거래가 30건보다 적어 AI는 아직 배우는 중이에요."
- J3: 연습용 거래의 기본값(인물·번호)은 'AI만 먼저 잡은 거래(only_ai)'가 1건 이상 나오는 조합으로 바꾼다. 백엔드가 찾고 테스트로 고정한다. 평가(eval) 시드와는 별개다.
  - 연습용 거래 응답에 `ai_only` 건수를 더한다.

### E. 기타 기능 (FN-01, AUG-02·03·04·06·07·09·10, J5·J6·J8·J9·J10·J11)

- **insights**
  - '지난달보다' 비교는 지난달의 같은 날짜 범위(1일~기준일)로 한다.
  - 응답에 `compare: {"prev_same_period_out", "days"}`를 더한다.
  - 시간대 이름은 앱의 시각 표기와 맞춘다: 새벽(밤 12시~아침 6시)·오전(6시~낮 12시)·낮(12시~저녁 6시)·저녁·밤(6시~밤 12시).
- **.xlsx 실제 지원** (AUG-02)
  - loader가 표준 라이브러리(zipfile + xml.etree)만으로 첫 시트를 읽어 기존 표 처리로 넘긴다. 공유 문자열·인라인 문자열·숫자를 읽고, 날짜 열의 엑셀 일련번호는 날짜로 바꾼다.
  - 크기 제한(압축 해제 합계 상한)으로 압축 폭탄을 막는다.
  - Pyodide에서도 동작해야 한다(엔진 모드에서 확인).
  - 화면 칩은 지금 가능: `.csv .txt .xlsx`, 준비 중: `.pdf .jpg .png`이고 accept도 갱신한다.
- **이어 붙여 올리기** (AUG-03)
  - 올리기 요청에 `mode: "replace" | "append"`를 받는다(기본 replace).
  - append는 기존 거래 뒤에 붙이고, 같은 거래(시각·금액·방향·방법·상대 정규화 같음)는 한 번만 둔다.
  - flags·reviews는 유지한다. 응답에 `added`, `duplicates`를 넣는다.
- **알린 거래 표시** (AUG-04): transactions·cards 항목에 `notified_at`(직접 보낸 기록 가운데 그 거래가 든 가장 최근 시각)을 넣고, 화면은 '알렸어요(날짜)' 배지를 보인다.
- **보낸 알림 다시 보내기·지우기** (AUG-06)
  - `POST /api/notices/remove {id}`는 직접 보낸 기록만 지운다.
  - 다시 보내기는 같은 받는 사람·글로 알림 보내기를 연다.
- **올리기 성공 요약** (AUG-07): "꼭 확인할 거래 N건·확인할 거래 M건" + [알림에서 보기]
- **거래 검색·기간** (AUG-09): 이름 검색, 기간(최근 1·3개월·전체)
  - 홈 TOP 3를 누르면 그 이름으로 걸러진 내 거래로 간다(J9).
- **같은 일 묶기** (J5): 알림 탭에서 같은 신호·같은 상대가 7일 안에 이어지면 "같은 일 N건"으로 묶고 펼칠 수 있게 한다.
- **유형별 지금 할 수 있는 일** (J6): 신호마다 짧은 행동 안내 1~2줄을 둔다. **1차 출처(기관 누리집)로 확인한 사실만 쓴다.** 확인 못 한 기관명·번호·서비스명은 쓰지 않는다.
  - 카드 빼앗기·현금 찾기 유형은 아직 약속(규칙)이 없다는 한계를 AI와 데이터 설명에 적는다.
- **카드 → 거래 자세히** (J8): 알림 카드에서 [자세히]를 누르면 거래 시트(같은 모양)를 연다.
- **사용법 다시 보기** (J10): 전체 탭 '사용법 안내'를 실제로 동작하게 만든다(첫 실행 1단계 소개를 다시 보여 주는 화면, 동의 단계 없이).
- **성능 표 결론 한 줄** (J11): 예) "AI를 더하면 꼭 확인할 일을 더 많이 찾지만, 괜찮은 거래 알림도 조금 늘어요." 수치는 표 그대로다.
- **조력자·기관용 요약 한 장** (AUG-10): 지금 만들 수 있는 텍스트 요약 저장. 이름·계좌 없이 집계만 담는다.
  - PDF 보고서는 준비 중으로 그대로 둔다.
- **J15** '잠깐 멈추기(나중에 다시 보기)'는 알림을 띄우려면 알림 권한이 필요하다. 권한 0개 원칙과 맞지 않아 이번에는 하지 않는다. 대신 휴대폰 알림 받기 준비 중 시트에 '다시 알려 주기' 단계를 자리표시로 넣는다.

### F. 자리표시 추가 (IA-2·3·4·6, AUG-11~15)

모두 '준비 중' 배지와 "정식 버전에서 열려요."를 붙이고, 동작하는 척하지 않는다.

- 계정: 로그인·로그아웃·탈퇴
- 데이터 옮기기(기기 변경)·백업·복원
- 휴대폰 결제내역 불러오기(통신사)
- 신고 도와주기(경찰·금융감독원 연결)·은행에 지급정지 요청 연계
- 정기 리포트(매달 조력자·상담하는 곳에 요약 보내기)
- 휴대폰 알림 받기 시트에 '알림 받을 때·조용한 시간·다시 알려 주기' 단계
- 은행·카드 연결 시트에 '정보 보내기 동의'와 '연결 완료' 단계
- 계좌 연결해서 바로 보내기 시트
  - '마이데이터로'라는 말을 뺀다. 마이데이터는 조회 전용이다.
  - "계좌를 연결해(오픈뱅킹) 이 앱에서 바로 보내요"와 '출금 동의' 단계를 쓴다.
- 첫 실행에 이용약관·개인정보 처리방침 동의 자리(준비 중 표기, 지금은 필수 아님)

### G. 문구·용어

- 담기 용어를 하나로 맞춘다: 버튼 "알림 목록에 담기"·"담기 취소", 토스트 "알림 탭에 담았어요.", 목록 "담은 거래", 배지 "담음"
- 당사자 화면에서 '심사·시연용'·'제안서'를 뺀다. 예시 칩은 "예시로 해 보기"로만 표기한다.
- 조력자·보호자 용어를 정리한다. 당사자 화면은 '조력자'를 쓴다. 전체 탭의 '보호자·심사용' 구역은 '조력자·기관용'으로 바꾼다.
- 동의 '상담하는 곳에 알려 주기' 설명(C2)
  - 사용자 요구 문장 "상담하는 곳에 알려 줘요."는 유지한다.
  - 바로 뒤에 실제 동작을 한 줄로 밝힌다: "알릴 때가 되면 알려 드려요. 보내기는 내가 눌러요."
- 모든 화면 문장은 한 문장 한 줄이다. 토스트·띠·li·표 칸도 문장을 나눈다.
- '이 기기'를 하드코딩하지 않는다(deviceWord).
- 맞춤법을 고친다: 이 곳→이곳, 찾아 보세요→찾아보세요, 을(를) 같은 표기 정리.

## 2. 화면 공용 계약 (화면 공용 담당이 만들고, 화면 담당은 이 이름만 쓴다)

| 위치 | 이름 | 동작 |
|---|---|---|
| components.js | `aiExplain(item)` | 위 D의 '왜 걱정되나요' 두 갈래 요소(규칙 신호 목록 + AI가 본 것)를 돌려준다. item.ai가 없으면 규칙만 보인다. |
| components.js | `reviewBadge(item)` / `notifiedBadge(item)` / `flagBadge(item)` | 해당 상태면 배지 요소, 아니면 null |
| components.js | `speakButton` | 버튼이 DOM에서 떨어지거나 같은 화면 안에서 패널이 바뀌면 읽기를 멈추고 상태를 되돌린다(MutationObserver 등 공통 처리). 화면 담당은 따로 stop을 부르지 않아도 된다. 시트가 닫힐 때도 멈춘다(ui.openSheet close). |
