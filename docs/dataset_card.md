# 데이터셋 카드: SafePause 합성 거래 데이터

## 1. 무엇인가

- `safepause/data/synth.py`가 만드는 **가상 인물의 합성 거래**입니다.
- **공개 통계로 보정한 데이터가 아닙니다.** 제안서 S19의 착취 시그널 5종을 재현하려고 설계한 **가정 기반 시나리오**입니다.
  인물 설정(소득·결제 빈도·금액)과 상대 이름·계좌·가맹점·통신사·회선은 모두 지어낸 값입니다.
- 실제 사람의 거래, 실제 착취 피해 사례를 쓰지 않았습니다.
- 용도: 기능 시연(화면·`demo`), 자동 테스트, 성능 비교 평가(`eval`). 실제 탐지 성능을 주장하는 근거로 쓰면 안 됩니다.

## 2. 만드는 법과 재현

```python
from safepause.data import synth
txns = synth.make_dataset("worker", seed=1, days=120, scenarios=synth.ALL_SCENARIOS)
```

- 난수는 모두 `numpy.random.default_rng(seed)`에서 나옵니다. 같은 인물·seed·기간 → 같은 거래.
- 기간 시작일은 `2026-03-02`로 고정(`synth.DEFAULT_START`). 기본 120일.
- 정상 부분은 시나리오를 넣든 안 넣든 같습니다(같은 seed의 정상 전용 **대조군**을 만들 수 있음).
- 시나리오는 종류마다 1회, **데이터 마지막 30일 안**에 넣습니다. 위치·내용은 (seed, 인물, 시나리오 종류)로 정한 하위 seed를 따릅니다.
- 평가(`eval`)는 앞 90일의 정상 거래로 학습하고 뒤 30일을 판단합니다. 따라서 시나리오는 학습 구간에 섞이지 않습니다.
- 예시 파일 3개와 seed는 [sample_data/README.md](../sample_data/README.md)에 있습니다.

## 3. 열 (SafePause 표준 CSV)

`id, ts, amount, direction, channel, counterparty, counterparty_id, line_id, memo, label`

- `amount`: 원 단위 양의 정수. `direction`: `out`/`in`. `channel`: `transfer`, `card`, `micropay`, `telecom_bill`, `atm`, `income`.
- `line_id`: 회선(가운데 가림, 예: `010-****-1234`).
- `label`: 정답 라벨. `normal` 또는 시나리오 코드. **평가와, 화면에서 합성 샘플의 AI 학습 구간 경계를 정하는 데만 씁니다.
  거래별 판단(룰·점수)에는 쓰지 않습니다.**

## 4. 가상 인물 3종 (가정값 전부, `synth.PERSONAS`)

| 항목 | worker (가상 근로자) | benefit (가상 복지급여 수급자) | student (가상 학생, 용돈) |
|---|---|---|---|
| 월 입금 | 190만 원(±5%), 매월 10일, "가상회사 급여" | 90만 원, 매월 20일, "복지급여" | 30만 원, 매월 1일, "아빠 용돈" |
| 카드결제 | 주 9건, 1건 평균 1만 1천 원 | 주 7건, 평균 8천 원 | 주 8건, 평균 6천 원 |
| 단골 가게 | 동네편의점, 회사 구내식당, 동네마트, 분식집, 카페, 약국 | 동네편의점, 동네마트, 복지관 식당, 약국, 빵집 | 학교 매점, 동네편의점, 분식집, 문구점, PC방 |
| 평소 송금 상대 | 엄마, 동생, 모임 회비 | 엄마, 활동 모임 회비 | 아빠, 친구 민수, 친구 지우 |
| 송금 | 월 4건, 1건 평균 5만 원 | 월 2건, 평균 4만 원 | 월 3건, 평균 1만 5천 원 |
| 통신요금(본인 회선 1개) | 5만 5천 원 내외, 매월 25일, 010-****-1234 | 3만 3천 원 내외, 15일, 010-****-5678 | 2만 5천 원 내외, 5일, 010-****-9012 |
| 휴대폰 소액결제 | 월 1건 | 월 1건 | 월 3건 |
| 현금 인출 | 월 1.5건 | 월 2건 | 월 1건 |
| 주 활동 시간 | 8~21시 | 8~21시 | 8~21시 |

금액·시각의 분포 가정:

- 하루 거래 건수는 포아송 분포(주당 건수 ÷ 7), 월 단위 사건(송금·소액결제·현금 인출 등)은 날마다 "월 건수 ÷ 30" 확률.
- 카드 금액: 평균을 맞춘 로그정규 분포(σ = 0.55), 100원 단위, 최소 1천 원. 송금 금액: 로그정규(σ = 0.5), 5천 원 단위, 최소 5천 원.
- 시각: 활동 시간 안에서 고르되 점심(12~13시)·저녁(18~20시)에 두 배 가중. 분·초는 균등.
  예외: 월 입금은 9~10시대, 통신요금은 10~11시대(분·초는 균등).
- 단골 고르기: 앞쪽 항목일수록 자주(가중치 1/순번).
- 소액결제 1건 1천~1만 5천 원(100원 단위), 현금 인출 1·2·3·5·10만 원 중 하나.

### 정상 이력의 잡음 (오탐을 의미 있게 재기 위한 가정)

| 잡음 | worker | benefit | student |
|---|---|---|---|
| 카드결제 중 처음 가는 가게 소액(3만 원 이하) 비율 | 6% | 6% | 6% |
| 밤(23~01시) 카드결제, 월 | 2건 | 1건 | 2.5건 |

| 처음 가는 가게 조금 큰 결제(5만~15만 원), 월 | 0.3건 | 0.15건 | 0.1건 |

처음 가는 가게는 15곳의 가상 목록(국밥집, 꽃집, 영화관 …)에서, 처음 보는 송금 상대는 가운데를 가린 가상 이름 10개(김*호 …)에서 고릅니다.

## 5. 시나리오 5종 (제안서 S19)

주입 거래는 `label`에 시나리오 코드가 붙습니다. 개인 기준값(카드 p95, 평소 7일 송금 합계)은 주입 시작일 이전 거래로 계산합니다.

| 코드 | 재현하는 착취 시그널 | 주입 내용(가정) |
|---|---|---|
| `night_repeat_transfer` | 심야 시간대 반복 이체 | 3~5일에 걸쳐 00~04시에, 처음 보는 상대 1명에게 이체 4~6건(각 10만~50만 원) |
| `payee_surge` | 특정 계좌 앞 송금 급증 | 처음 보는 상대 1명에게 7일 안에 4~7건, 합계는 평소 7일 송금 합계의 9~12배(최소 30만~60만 원), 9~20시 |
| `micropay_surge` | 통신 소액결제 급증 | 7일 안에 본인 회선 휴대폰 소액결제 8~15건(각 1만~10만 원), 9~22시 |
| `new_merchant_high_value` | 신규 가맹점 고액 결제 과다 | 6일 안에 처음 보는 가맹점 2~4곳, 금액은 max(개인 카드 p95×3, 10만 원)의 1.2~2.5배 |
| `multi_line_telecom` | 단기간 다회선 통신요금 청구 | 14일 안에 서로 다른 새 회선 2~3개의 통신요금 청구(명의도용 개통 재현), 각 3만 5천~9만 8,990원 |

- 시나리오 금액·건수는 룰 기준(SPEC §5)을 넘도록 여유를 두고 정했습니다. 예를 들어 송금 급증은 기준(5배)보다 큰
  9~12배로 넣어, 주입 거래가 뒤 거래의 '평소' 기준에 섞여도 기준을 넘게 했습니다. **따라서 룰 탐지율이 높은 것은 설계의 결과입니다.**
- 실제 착취는 더 천천히, 더 작은 금액으로, 여러 방법을 섞어 일어날 수 있습니다. 이런 경우는 표준 시나리오가 나타내지 않습니다.
  그 일부를 아래 경계 변형으로 따로 만들었습니다.

### 5.1 경계 변형(subtle) 시나리오 (`intensity="subtle"`)

룰 기준에 못 미치거나 겨우 닿게 줄인 변형입니다. AI 이상탐지가 룰에 더하는 몫을 재려고 만들었습니다.
정의는 결과를 보기 전에 SPEC.md §3 [추가 r4]에 적었고, 결과를 본 뒤 바꾸지 않았습니다.
`synth.make_dataset(..., intensity="subtle")`로 만들며, 평가는 `python -m safepause eval --seeds 20 --intensity subtle --out docs/eval`입니다.

| 코드 | 주입 내용(가정) |
|---|---|
| `night_repeat_transfer` | 7일 안 00~04시에 처음 보는 상대 1명에게 이체 2건, 각 30만~80만 원(1만 원 단위) |
| `payee_surge` | 처음 보는 상대 1명에게 7일 안 이체 2건(9~20시), 합계 = 평소 7일 송금 합계 × 2.0~2.9(평소 합계가 0이면 20만~29만 원) |
| `micropay_surge` | 7일 안 본인 회선 휴대폰 소액결제 4건, 각 5만~10만 원(1천 원 단위), 9~22시 |
| `new_merchant_high_value` | 처음 보는 가맹점 1곳에서 카드결제 1건(10~20시), 금액 = max(개인 카드 p95 × 2.0~2.9, 10만 원) |
| `multi_line_telecom` | 처음 보는 회선 1개의 통신요금 청구 1건(시작일 9~18시), 3만 5천~9만 8,990원 |

- 개인 기준값(카드 p95, 평소 7일 송금 합계)은 표준과 같게 주입 시작일 이전 거래로 계산합니다.
- 배치는 표준과 같습니다: 종류마다 1회, 마지막 30일 안, 위치와 하위 seed를 정하는 방식도 같습니다.
  같은 seed면 정상 거래는 표준·경계 변형·대조군에서 모두 같습니다. 라벨도 표준과 같은 시나리오 코드입니다.
- 룰 기준과의 관계(SPEC §3 [추가 r4]): '못 미친다'는 모든 룰의 '주의' 기준 아래라는 뜻이 아닙니다.
  심야 반복 이체 2건은 심야 룰의 '주의' 기준(2건)에 닿고, 같은 새 상대에게 30만 원 이상을 두 번 보내므로 특정 계좌 송금 급증 룰이
  함께 발동할 수 있습니다(룰만 방식 평가에서 60사례 모두 고위험, 그중 57사례는 심야 룰이 아니라 송금 급증 룰이 고위험을 냄).
  신규 가맹점은 10만 원 하한 때문에 룰의 '주의' 기준에 닿을 수 있고, 새 회선 1개는 본인 회선이 최근 30일 안에 청구됐으면 '주의' 기준에 닿습니다.
- 이 변형도 가정입니다. 실제 착취 거래가 이런 모양이라는 근거는 없습니다. 결과는 [eval/eval_report.md](eval/eval_report.md) 6절과 README 5장에 있습니다.

## 6. 알려진 한계

- 인물 3종의 값은 가정입니다. 실제 발달장애인의 소득·소비 분포를 대표하지 않습니다.
- 계절·명절·월말 효과, 자동이체, 환불·취소, 여러 계좌·카드, 가족 공동 계좌 같은 현실의 복잡함이 없습니다.
- 모든 거래에 시각이 있습니다. 실제 은행 파일은 날짜만 있을 수 있습니다(가져오기에서는 낮 12시로 둠).
- 한 사례에 시나리오 5종이 모두 같은 마지막 30일 안에 겹쳐 들어갑니다(예: worker seed 1은 송금 급증 05-31~06-04, 소액결제 06-10~06-15,
  다회선 06-16~06-26, 심야 06-25~06-27). 이런 동시 발생을 가정할 근거는 없고, 한 시나리오의 거래가 다른 판단의 이력이 되어
  겹친 기간에는 정상 거래 알림이 늘어납니다([eval_report](eval/eval_report.md) §3.1 '시나리오와 겹쳐 함께 알림').
- 합성 데이터만으로 잰 성능은 실제 성능을 보장하지 않습니다. 실제 거래내역으로는 "내 거래로 확인"(정상 가정의 알림 비율)만 어림할 수 있습니다.
- 평가 seed: seed 1~20은 r1~r3 룰 보완 때 결과를 본 표본(표본 안)이고, seed 21~40은 룰 보완에 쓰지 않은 별도 검증 세트입니다
  (SPEC.md §8 [추가 r5], [eval_report](eval/eval_report.md) 7절). 두 묶음 모두 같은 생성기·같은 인물 설정이라, 검증 세트도 다른 분포에서의
  성능을 보여 주지 않습니다.
