# SafePause (안전 정지)

지원의사결정 기반 발달장애인 경제적 착취 사전 예방 AI 모니터링 시스템의 **실행 가능한 프로토타입**입니다.
2026 AI 라이프 솔루션 챌린지 제출용으로 만들었습니다.

- 돈이 나가기 전에 위험 신호가 보이면, 당사자에게 쉬운 말·그림 카드로 **잠깐 멈춰 다시 생각할 기회(Safe Pause)** 를 줍니다.
- **막지 않습니다.** "그래도 보낼래요"를 고르면 그대로 진행됩니다. 최종 결정은 당사자가 합니다.
- 당사자가 동의하고 정한 신뢰 조력자에게만, 당사자가 정한 범위에서 알림을 **기록**합니다(실제 문자·메일 발송 없음).
- 모든 판단은 이 컴퓨터 안(127.0.0.1)에서만 합니다. 외부로 거래 데이터를 보내지 않습니다.

> **알아 두기**
> - 연습용 프로그램입니다. 실제 송금·결제·알림 발송 기능이 없습니다.
> - 성능 수치는 **합성 데이터 기준, 실제 피해 데이터 검증 아님**입니다. 합성 데이터는 공개 통계로 보정하지 않은 가정 기반 시나리오입니다([docs/dataset_card.md](docs/dataset_card.md)).
> - 특정 은행·카드사 파일 양식을 지원한다는 뜻이 아닙니다. 실제 금융기관 파일로 시험한 적이 없습니다.

## 1. 실행하기 (심사위원용)

아래 방법 중 하나를 고르세요. **Windows에서는 ⓪ SafePause.exe가 가장 간단합니다(설치 불필요).** Python이 있거나 macOS·Linux라면 ① 소스 실행을 쓰세요. 확인 범위는 8장에 적었습니다.

### ⓪ SafePause.exe (Windows, 설치 불필요, 권장)

1. `SafePause.exe`를 짧은 경로의 폴더(예: `C:\SafePause`)에 두고 **더블클릭**합니다. Python을 설치할 필요가 없습니다.
2. 검은 창에 주소(`http://127.0.0.1:8765`)가 나오고 기본 브라우저가 화면을 엽니다. 브라우저가 열리지 않으면 창에 나온 주소를 브라우저에 붙여 넣으세요.
3. 끝내려면 검은 창에서 `Ctrl+C`를 누르거나 창을 닫습니다.

- **"Windows의 PC 보호"(SmartScreen) 창이 뜨면:** 이 파일은 코드 서명을 하지 않았습니다. 인터넷에서 받은 서명 없는 실행파일에는 이 경고가 뜰 수 있습니다. **[추가 정보] → [실행]**을 누르면 됩니다. 걱정되면 ① 소스 실행으로 같은 프로그램을 확인할 수 있습니다(exe는 이 소스를 `packaging\safepause.spec`으로 묶은 것).
- 콘솔 명령도 됩니다: `SafePause.exe demo`(샘플 판단 결과 보기), `SafePause.exe eval --seeds 5`(성능 평가), `SafePause.exe --port 9000`.
- 처음 실행할 때 파일을 임시 폴더에 풀기 때문에 화면이 뜨기까지 몇 초 걸립니다(작성 PC에서 서버 응답까지 약 3초, 8장).
- 저장 폴더는 `%LOCALAPPDATA%\SafePause`입니다. ⑦ 화면이나 `SafePause.exe wipe`로 지울 수 있습니다.

### 준비 (① ② 소스 실행용)

- **Python 3.10 이상** ([python.org](https://www.python.org/downloads/)). 개발·확인은 Python 3.12.10(Windows 11)에서 했습니다.
- 처음 한 번은 패키지 설치를 위해 **인터넷**이 필요합니다. 설치 뒤 실행에는 인터넷이 필요 없습니다.
- **Windows: 짧은 경로에 풀어 주세요.** 예: `C:\SafePause`. 폴더 경로가 길면(대략 140자 넘음) Windows 기본 설정에서
  scikit-learn 설치가 파일 경로 길이 제한으로 실패할 수 있습니다. `run_windows.bat`는 경로가 100자를 넘으면 미리 알려 줍니다.

### ① 소스 실행 (권장)

| 운영체제 | 실행 |
|---|---|
| Windows | 압축을 푼 폴더에서 `run_windows.bat`를 더블클릭 |
| macOS·Linux | 터미널에서 `sh run_mac_linux.sh` (기본 `python3`가 3.10보다 오래됐으면 `PYTHON=python3.12 sh run_mac_linux.sh`) |

1. 처음 실행하면 폴더 안에 가상환경 `.venv`를 만들고 `requirements.txt`의 패키지를 설치합니다.
2. 서버가 `http://127.0.0.1:8765`에서 열리고 기본 브라우저가 화면을 띄웁니다.
   포트가 사용 중이면 다음 번호(8766, 8767 …)로 열고, 창에 실제 주소를 보여 줍니다.
3. 끝내려면 창에서 `Ctrl+C`를 누릅니다.
4. 같은 저장 폴더로 이미 켜져 있으면(예: 두 번 실행) 서버를 하나 더 띄우지 않고, 켜져 있는 화면 주소를 알려 주고 엽니다.

추가 인자는 `serve` 명령에 그대로 전달됩니다. 예: `run_windows.bat --port 9000 --no-browser`

문제가 생기면:

- "Python 3.10 이상을 찾지 못했어요" → Python을 설치하고(설치 화면의 *Add python.exe to PATH* 선택) 다시 실행하세요.
- "패키지 설치에 실패했어요" → 인터넷 연결을 확인하고, 경로가 길면 `C:\SafePause`처럼 짧은 폴더로 옮긴 뒤
  `.venv` 폴더를 지우고 다시 실행하세요.
- ".venv 폴더의 Python을 실행하지 못했어요" → 다른 컴퓨터에서 복사된 `.venv`입니다. `.venv` 폴더를 지우고 다시 실행하세요.
- (macOS·Linux) "Python 3.10 이상이 필요해요" → 새 Python을 설치한 뒤 `rm -rf .venv && PYTHON=python3.12 sh run_mac_linux.sh`
  (`python3.12` 자리에 설치한 Python 명령 이름).

### ② 명령행 (Python에 직접 설치)

활성화(activate) 없이 가상환경의 Python을 직접 부르면 운영체제·셸과 관계없이 됩니다.

Windows(cmd·PowerShell 모두):

```bat
py -3 -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python -m safepause serve
.venv\Scripts\python -m safepause demo
```

`py` 명령이 없으면 첫 줄을 `python -m venv .venv`로 바꿉니다. `serve`는 화면 열기, `demo`는 콘솔에서 샘플 3건의 판단 결과와 카드 보기입니다.

macOS·Linux(`python` 명령이 없는 시스템이 많아 `python3`을 씁니다):

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m safepause serve
.venv/bin/python -m safepause demo
```

- Windows의 python.org 설치 프로그램은 *Add python.exe to PATH*가 기본으로 꺼져 있어, `python`이 Microsoft Store 안내로
  연결될 수 있습니다. 그래서 `py -3`(Python 런처, python.org 설치 프로그램이 함께 설치)을 먼저 씁니다. `run_windows.bat`도 같은 순서입니다.

- Windows PowerShell에서 `.venv\Scripts\activate`는 기본 실행 정책(Restricted)이면 "running scripts is disabled"로 막힙니다.
  그때 활성화가 안 된 채 `pip install`을 치면 **전역 Python에** 패키지가 깔립니다. 위처럼 `.venv\Scripts\python`을 쓰거나,
  cmd 창에서 `.venv\Scripts\activate.bat`를 쓰거나, 그 PowerShell 창에만 `Set-ExecutionPolicy -Scope Process Bypass`를 준 뒤 활성화하세요.
- 아래 3장의 `python`은 가상환경의 Python(활성화했거나 `.venv\Scripts\python`)을 뜻합니다.

명령은 **`python -m safepause …` 형식**을 쓰세요. `run_windows.bat`·`requirements.txt` 설치는 패키지 자체를 설치하지 않으므로
`safepause`라는 콘솔 명령은 없습니다. `pip install .`로 설치하면 `safepause …`도 쓸 수 있습니다.

### ③ SafePause.exe 직접 빌드하기 (선택)

`packaging\build_exe.bat`를 실행하면 가상환경을 만들고 PyInstaller로 `dist\SafePause.exe`(단일 파일)를 만듭니다. 빌드에는 인터넷(패키지 설치)이 필요하고 작성 PC에서 약 1분 걸렸습니다.

## 2. 5분 체험 시나리오

화면은 7개 탭입니다: ①동의 ②내 거래 ③보내기 연습 ④알림 카드 ⑤조력자 ⑥성능 확인 ⑦내 데이터 지우기.

1. **① 동의**: "거래 살펴보기"를 켭니다. (조력자 알림·상담 연결은 따로 켜고 끕니다. 끄면 바로 멈춥니다.)
2. **② 내 거래**: "가상 근로자" + "걱정되는 거래 섞기"로 **불러오기**. 가상 거래 232건이 저장되고,
   거래마다 "괜찮아요 / 확인해요 / 꼭 확인해요"와 이유(시그널)가 붙습니다. "꼭 확인할 것만"으로 걸러 볼 수 있습니다.
3. **⑤ 조력자**: "조력자 더하기"로 예를 들어 엄마(무엇을 알릴까요: 모든 것), 아빠(휴대폰 요금이 여러 개만)를 저장합니다.
   연락처는 가려서 저장됩니다(예: `010-****-5678`).
   "이 조력자에게 자동으로 알리기"를 끄면 그 사람에게는 자동으로 알리지 않고, 카드에서 "조력자에게 물어볼래요"로 고를 때만 알립니다.
4. **① 동의**에서 "조력자에게 알리기"도 켭니다.
5. **③ 보내기 연습**: 예시 "김*호에게 30만 원 (새벽 2시)" → **보내기**.
   - 안전 정지 카드가 뜹니다: 그림 + 쉬운 말 + "이 돈을 정말 보내는 것이 맞나요?" + 선택지 3개.
   - 고르기 전에 누가 알게 되는지 카드에 나옵니다(예: "엄마에게 알려 드릴게요.").
   - "조력자에게 물어볼래요"를 고르면 **물어볼 사람을 직접 고르는 화면**이 나옵니다(기본값: 내가 정한 범위 안의 조력자).
     ⑤에서 정한 대로 자동으로 알리는 조력자는 체크를 풀 수 없고, 그 까닭이 적혀 있습니다.
     물어볼 조력자가 없으면(등록 안 함, 또는 모두 돈을 받는 사람) 요청을 보내지 않고 까닭을 보여 줍니다.
   - 이 컴퓨터에 한국어 음성이 있으면 "소리로 듣기"로 카드를 읽어 줍니다.
6. 예시 "처음 가는 가게에서 80만 원 결제"도 해 보세요. 결제에는 "이 돈을 정말 내는 것이 맞나요? / 그래도 낼래요"처럼
   거래 방법에 맞는 말을 씁니다. 어떤 선택을 해도 실제로 돈이 나가지 않습니다.
7. **④ 알림 카드**: 걱정했던 지난 거래가 과거형 카드로 보입니다. **⑤ 조력자** 아래에 알림 기록이 있습니다.
8. **⑥ 성능 확인**: "규칙만"·"AI만"도 체크한 뒤 "확인 시작"(합성 데이터로 3개 방식 비교. 처음에는 "규칙 + AI 함께" 한 가지만 체크되어 있음)
   또는 "내 거래로 확인"(저장된 거래로 알림 비율 어림).
9. **⑦ 내 데이터 지우기**: 동의·조력자·거래·기록을 모두 지웁니다(즉시 철회권).

명령행으로도 체험할 수 있습니다: `python -m safepause demo`

## 3. 명령 모음

| 명령 | 하는 일 |
|---|---|
| `python -m safepause serve [--port 8765] [--no-browser] [--home 폴더]` | 로컬 서버(127.0.0.1 전용) + 브라우저 화면 |
| `python -m safepause demo [--persona worker] [--seed 1]` | 합성 데이터로 샘플 3건의 판단·카드·조력자 계획 출력 |
| `python -m safepause synth --persona worker --seed 1 --out a.csv [--no-scenarios]` | 합성 거래 CSV 만들기 |
| `python -m safepause analyze --file 내거래.csv [--mapping map.json] [--out 폴더]` | 거래내역 CSV를 읽어 알림 목록 출력. SafePause 저장소에는 넣지 않음. `--out`을 주면 받는 곳·금액이 든 보고서 파일을 씀(`wipe`는 이 파일을 지우지 않음) |
| `python -m safepause eval [--seeds 20] [--seed-start 1] [--intensity standard\|subtle] [--out eval_out]` | 결합·룰·AI 3개 방식 비교 평가 + 보고서(기본 폴더 `eval_out`). `--intensity subtle`은 룰 기준에 못 미치게 줄인 경계 변형 시나리오(5장). `--seed-start`가 1이 아니면 별도 검증 세트로 보고 `eval_results_holdout.json`(경계 변형은 `eval_results_subtle_holdout.json`)에 따로 씀 |
| `python -m safepause wipe [--yes] [--home 폴더]` | 저장 데이터 모두 지우기 |

- 저장 폴더: 환경변수 `SAFEPAUSE_HOME` → Windows `%LOCALAPPDATA%\SafePause` → 그 밖 `~/.safepause`.
- **빠른 평가 확인은 다른 폴더로**: `python -m safepause eval --seeds 3 --out 다른폴더`. 제출 보고서 `docs/eval`(20-seed)에는
  다른 설정의 결과를 덮어쓰지 않습니다(덮어쓰려면 `--overwrite`). 같은 결과를 다시 만들려면 `--seeds 20 --out docs/eval`,
  경계 변형은 `--seeds 20 --intensity subtle --out docs/eval`, 별도 검증 세트(seed 21~40)는 두 명령에 `--seed-start 21`을 더합니다.
- 서버가 켜져 있을 때는 화면의 **⑦ 내 데이터 지우기**를 쓰세요. 밖에서 `wipe`로 지워도 서버는 저장 파일이 바뀐 것을
  알아채고 지운 거래를 다시 쓰지 않습니다.
- 거래내역 CSV: 한국어 머리글(`거래일시`, `출금액`/`입금액`, `내용` 등)을 보고 열을 추정합니다. 추정한 내용은 결과의 "알아 두기"에
  적힙니다. 열 이름을 알아보지 못하면 `--mapping`(화면에서는 "열 이름 직접 알려 주기")으로 지정합니다.
  예시 파일: [sample_data/bank_export_example.csv](sample_data/bank_export_example.csv) (가상 양식), 설명: [sample_data/README.md](sample_data/README.md).

### 테스트

```bash
python -m pip install "pytest>=8" "httpx>=0.27,<0.28"
python -m pytest -q
```

httpx 0.28은 요구 범위의 하한인 fastapi 0.110(starlette 0.36)의 테스트 도구와 맞지 않아 0.27로 둡니다.

## 4. 기능 ↔ 제안서 대응표

**S 번호**는 제출 제안서 자체의 번호가 아닙니다(제안서에는 번호가 없음). 이 문서들에서 제출 제안서 본문(1~3쪽)을 제목과 항목(ㅇ, -)마다 위에서부터 차례로 센 번호입니다. 여기서 쓰는 번호의 위치는 다음과 같습니다.

| S | 제출 제안서 위치 | S | 제출 제안서 위치 |
|---|---|---|---|
| S6 | 제안서요약 첫 ㅇ(동의 기반 실시간 분석) | S21 | 아이디어 둘째 ㅇ 아래 -(강제 차단 대신 본인 결정) |
| S10 | 제안배경 첫 ㅇ 아래 첫 -(2024 장애인학대 현황 통계) | S22 | 아이디어 셋째 ㅇ(신뢰 조력자 2차 알림) |
| S18 | 아이디어(제안내용) 첫 ㅇ(마이데이터 상시 분석) | S23 | 아이디어 셋째 ㅇ 아래 -(반복 고위험 시 상담 연계) |
| S19 | 아이디어 첫 ㅇ 아래 -(착취 시그널 나열) | S35 | 기술구현 유의점 첫 ㅇ 아래 -(마이데이터 API·온디바이스) |

## 5. 성능 요약 (합성 데이터 기준, 실제 피해 데이터 검증 아님)

> **표본 안과 별도 검증 세트를 나눠 읽어 주세요.** 아래 "표준 시나리오"·"경계 변형" 두 표는 seed 1~20 값입니다.
> r1~r3에서 룰 기준을 이 seed들의 평가(특히 시나리오 없는 대조군 60사례)를 보며 보완했으므로 **표본 안(in-sample) 값**입니다.
> 룰 보완에 쓰지 않은 seed 21~40으로 같은 평가를 다시 한 **별도 검증 세트** 값은 이 장 끝에 따로 적었습니다.

### 표준 시나리오 (seed 1~20, 표본 안)

`python -m safepause eval --seeds 20 --out docs/eval` 결과 파일([docs/eval/eval_report.md](docs/eval/eval_report.md),
[eval_results.json](docs/eval/eval_results.json))에서 옮겼습니다. 인물 3종 × seed 20개(1~20) = 60사례, 사례마다 앞 90일로 배우고 뒤 30일을 판단했습니다.

| 방식 | 시나리오 탐지(주의 이상) | 시나리오 탐지(고위험) | 정상 거래 알림률 | 대조군 월평균 알림 | 대조군 월평균 고위험 |
|---|---|---|---|---|---|
| 결합(룰+AI, 앱 기본) | 100.0% (300/300) | 100.0% (300/300) | 1.84% | 0.18건 | 0.03건 |
| 룰만 | 100.0% (300/300) | 100.0% (300/300) | 1.51% | 0.03건 | 0건 |
| AI 이상탐지만 | 100.0% (300/300) | 54.7% (164/300) | 9.69% | 3.60건 | 0.15건 |

- 대조군: 같은 seed로 시나리오 없이 만든 정상 데이터. "월평균"은 인물 1명의 30일당 건수입니다.
- 시나리오는 룰 기준을 넘도록 설계했으므로 룰 탐지율 100%는 설계의 결과이며 실제 탐지율을 뜻하지 않습니다.
  그래서 이 표에서는 AI 이상탐지가 룰에 더하는 몫이 보이지 않습니다. 그 몫은 아래 경계 변형 실험에서 쟀습니다.
- 한계와 해석은 [docs/eval/eval_report.md](docs/eval/eval_report.md)의 "해석 시 유의점"과 [docs/model_card.md](docs/model_card.md)를 보세요.

### 경계 변형(subtle) 실험: 룰 기준에 못 미치게 줄인 시나리오 (seed 1~20, 표본 안)

시나리오 5종을 룰 기준에 못 미치거나 겨우 닿게 줄인 변형을 만들어, 같은 설정(인물 3종 × seed 20(1~20) = 60사례, 시나리오 300개)으로
세 방식을 비교했습니다. 변형 정의와 비교 방법은 결과를 보기 전에 [SPEC.md](SPEC.md) §3·§8 [추가 r4]에 적었고,
결과를 본 뒤 정의·룰·기준값을 바꾸지 않았습니다. 재현: `python -m safepause eval --seeds 20 --intensity subtle --out docs/eval`
→ [eval_results_subtle.json](docs/eval/eval_results_subtle.json), [eval_report.md](docs/eval/eval_report.md) 6절.

| 방식 | 시나리오 탐지(주의 이상) | 시나리오 탐지(고위험) | 정상 거래 알림률 | 정상 거래 고위험률 |
|---|---|---|---|---|
| 결합(룰+AI, 앱 기본) | 73.3% (220/300) | 63.3% (190/300) | 0.74% (20/2,715건) | 0.33% (9건) |
| 룰만 | 66.0% (198/300) | 20.3% (61/300) | 0.48% (13/2,715건) | 0.04% (1건) |
| AI 이상탐지만 | 92.0% (276/300) | 40.3% (121/300) | 8.69% (236/2,715건) | 0.29% (8건) |

시나리오별 탐지 사례 수(주의 이상 / 고위험, 시나리오마다 60사례):

| 시나리오 | 결합 | 룰만 | AI만 | 결합 − 룰만 |
|---|---|---|---|---|
| 심야 반복 이체 | 60 / 60 | 60 / 60 | 60 / 59 | 0 / 0 |
| 특정 계좌 송금 급증 | 4 / 2 | 2 / 1 | 45 / 2 | +2 / +1 |
| 통신 소액결제 급증 | 38 / 18 | 18 / 0 | 60 / 32 | +20 / +18 |
| 신규 가맹점 고액 결제 | 60 / 56 | 60 / 0 | 56 / 8 | 0 / +56 |
| 단기간 다회선 통신요금 | 58 / 54 | 58 / 0 | 55 / 20 | 0 / +54 |

결합 − 룰만 차이(= AI 이상탐지가 룰 판단에 더한 몫):

- **주의 이상 탐지 +7.3%p(198 → 220/300)로 작습니다.** 룰이 놓친 사례를 AI 점수만으로 새로 잡은 것은 소액결제 20사례, 송금 급증 2사례뿐입니다.
- **고위험 탐지 +43.0%p(61 → 190/300).** 늘어난 129사례는 모두 룰이 이미 '주의'로 본 사례를 AI 점수(0.90 이상)가 '고위험'으로
  올린 것입니다(가맹점 56, 회선 54, 소액결제 18, 송금 급증 1). 결합 규칙상 AI 점수만으로는 고위험이 되지 않습니다.
  즉 이 실험에서 AI는 새로 찾기보다 룰이 찾은 것의 등급을 올리는 데 주로 쓰였습니다.
- **심야 반복 이체는 AI 기여 0%p**입니다. 룰만으로 60/60이 고위험인데, 그중 57사례는 심야 룰(7일 2건이라 '주의' 기준)이 아니라
  특정 계좌 송금 급증 룰(같은 새 상대에게 30만~80만 원을 두 번)이 고위험을 냈고, 3사례는 두 룰이 함께 냈습니다(결과를 본 뒤 원인만 확인).
- **특정 계좌 송금 급증은 결합 방식도 4/60만 잡았습니다.** AI만 방식은 45/60을 잡지만 정상 거래 알림률이 8.69%입니다.
- **대가(오탐 증가)**: 정상 거래 알림률 +0.26%p(13 → 20건), 고위험률 +0.29%p(1 → 9건). 정상 전용 대조군은 표준과 같은
  데이터라 월평균 알림·고위험도 위 표와 같습니다(결합 0.18/0.03건, 룰만 0.03/0건).
- 이 변형도 가정 기반입니다. 실제 착취 거래가 이런 모양이라는 근거는 없으며, 이 수치도 실제 탐지율을 뜻하지 않습니다.

### 별도 검증 세트 (seed 21~40, 룰 보완에 쓰지 않은 seed)

위 두 실험을 seed 21~40(인물 3종 × 20 = 60사례)으로 다시 돌렸습니다. 검증 세트와 지표는 결과를 보기 전에 [SPEC.md](SPEC.md) §8
[추가 r5]에 적었고, 결과를 본 뒤 룰·기준값·모델·합성 정의를 바꾸지 않았습니다. 재현:
`python -m safepause eval --seeds 20 --seed-start 21 --out docs/eval`(경계 변형은 같은 명령에 `--intensity subtle`)
→ [eval_results_holdout.json](docs/eval/eval_results_holdout.json), [eval_results_subtle_holdout.json](docs/eval/eval_results_subtle_holdout.json),
[eval_report.md](docs/eval/eval_report.md) 7절. 칸마다 **seed 1~20(표본 안) → seed 21~40(검증 세트)** 입니다.

| 강도 · 방식 | 시나리오 탐지(주의 이상) | 시나리오 탐지(고위험) | 거래 단위 고위험 재현율 | 정상 거래 알림률 | 정상 거래 고위험률 | 대조군 월평균 알림 | 대조군 월평균 고위험 |
|---|---|---|---|---|---|---|---|
| 표준 · 결합(앱 기본) | 100.0% → 100.0% | 100.0% → 100.0% | 79.1% → 78.5% | 1.84% → 1.45% | 1.36% → 1.05% | **0.18 → 0.23건** | **0.03 → 0.12건** |
| 표준 · 룰만 | 100.0% → 100.0% | 100.0% → 100.0% | 55.6% → 55.7% | 1.51% → 1.20% | 0.96% → 0.72% | **0.03 → 0.12건** | 0 → 0건 |
| 표준 · AI 이상탐지만 | 100.0% → 100.0% | 54.7% → 53.0% | 37.7% → 38.7% | 9.69% → 9.93% | 0.33% → 0.33% | 3.60 → 3.62건 | 0.15 → 0.12건 |
| 경계 변형 · 결합(앱 기본) | 73.3% → 74.3% | 63.3% → 63.0% | 43.0% → 41.7% | 0.74% → 0.80% | 0.33% → 0.54% | 0.18 → 0.23건 | 0.03 → 0.12건 |
| 경계 변형 · 룰만 | 66.0% → 64.7% | 20.3% → 21.0% | 10.2% → 10.5% | 0.48% → 0.58% | 0.04% → 0.07% | 0.03 → 0.12건 | 0 → 0건 |
| 경계 변형 · AI 이상탐지만 | 92.0% → 94.7% | 40.3% → 38.7% | 37.0% → 35.3% | 8.69% → 9.28% | 0.29% → 0.29% | 3.60 → 3.62건 | 0.15 → 0.12건 |

- **대조군 오탐은 검증 세트에서 더 높습니다.** 시나리오 없는 정상 데이터에서 앱 기본(결합) 방식의 1인당 월평균 알림이
  0.18건(60사례 합계 11건) → 0.23건(14건), 월평균 고위험(기본 설정에서 조력자 알림이 가는 등급)이 0.03건(2건) → 0.12건(7건)으로
  건수 기준 3.5배입니다. 룰만 방식도 월평균 알림 0.03건(2건) → 0.12건(7건)입니다. 검증 세트 대조군에서 룰만 방식의 고위험은 0건이므로,
  결합 방식 고위험 7건은 모두 룰이 '주의'로 본 거래(룰만 방식 알림 7건 전부)를 AI 점수(0.90 이상)가 '고위험'으로 올린 것입니다
  (결합 규칙상 AI 점수만으로는 고위험이 되지 않습니다. 표본 안에서도 2건 → 2건으로 같은 모양).
  표본 안의 낮은 대조군 값(특히 고위험 0.03건)에는 그 표본을 보며 룰을 맞춘 영향과 표본 변동이 섞여 있을 수 있고, 새 seed에서는
  검증 세트 값 정도를 예상하는 편이 덜 치우친 읽기입니다. 대조군은 강도와 관계없이 같은 데이터라 두 강도의 대조군 값이 같습니다.
- 시나리오가 섞인 데이터의 정상 거래 알림률은 표준에서 검증 세트가 더 낮았고(결합 1.84% → 1.45%), 경계 변형에서는 더 높았습니다
  (결합 0.74% → 0.80%, 고위험률 0.33%(9건) → 0.54%(15건)).
- 표준 시나리오 탐지율(결합·룰만 100%)은 검증 세트에서도 같습니다. 룰 기준을 넘게 설계한 시나리오라 예상된 결과이며 실제 탐지율을 뜻하지 않습니다.
- 경계 변형에서 AI 이상탐지가 룰에 더한 몫(결합 − 룰만)은 주의 이상 +7.3%p → +9.7%p(194 → 223/300), 고위험 +43.0%p → +42.0%p
  (63 → 189/300)로 비슷했습니다. 특정 계좌 송금 급증은 검증 세트에서도 결합 5/60(고위험 0/60)만 잡았습니다.
- 두 묶음 모두 같은 합성 생성기·같은 인물 설정이라, 검증 세트도 실제 거래나 다른 분포에서의 성능을 보여 주지 않습니다.
  60사례 두 묶음의 차이에는 표본 변동이 섞여 있습니다(예: 대조군 결합 고위험 2건 대 7건).

### 단순 규칙 대비 점검: AI가 등급을 올리는 몫은 판별력이 아니다 (seed 21~40)

결합 방식의 '룰 주의 + 점수 0.90 이상 → 고위험' 상향은 룰이 '주의'로 본 거래를 거의 모두 올립니다. 그래서 AI 없이 **'룰 주의 이상을 모두 고위험으로 본다'**는 단순 규칙과 성적이 거의 같습니다. 아래 표는 검증 세트 JSON의 룰만 방식 '주의 이상' 값과 결합 방식 '고위험' 값을 나란히 놓은 것입니다(새 실행 없음).

| 비교 (검증 세트) | 단순 규칙 = 룰만 '주의' 이상 | 결합 방식 '고위험' |
|---|---|---|
| 표준: 거래별 재현율 | 79.2% (1,306/1,650) | 78.5% (1,295/1,650) |
| 표준: 주입 사례 정상 거래 비율 | 1.20% (33/2,759) | 1.05% (29/2,759) |
| 경계 변형: 시나리오 탐지율 | 64.7% (194/300) | 63.0% (189/300) |
| 경계 변형: 주입 사례 정상 거래 비율 | 0.58% (16/2,759) | 0.54% (15/2,759) |
| 대조군 1인당 월평균 | 0.12건 (7건) | 0.12건 (7건) |

- 따라서 앞 절의 '룰만 → 결합 고위험 +42%p'는 AI의 판별력이라기보다 **룰 '주의'를 일괄로 한 단계 올린 효과**에 가깝습니다.
- AI만의 몫은 **룰이 못 본 출금에 '주의' 카드를 먼저 띄우는 경로**(룰 없음 + 출금 + 점수 0.98 이상)입니다. 표준 검증 세트에서 거래별 주의 이상 재현율 79.2% → 83.5%(1,306 → 1,378건), 첫 카드 전 평균 유출 95,771원 → 67,031원입니다. 대가로 대조군 월평균 알림 0.12 → 0.23건입니다.
- 개선 과제: 룰 발동 조건과 겹치는 특징(새 상대·새 회선 등)을 뺀 모델이나 거래 순서를 보는 모델로, 이 단순 규칙보다 나은지 새 seed로 검증.

## 6. 개인정보·오프라인 원칙

- **로컬 전용**: 서버는 `127.0.0.1`에만 열리고, Host 머리글이 loopback이 아니면 거절합니다. 상태를 바꾸는 요청에는
  화면이 붙이는 `X-SafePause: 1` 머리글이 늘 있어야 하고, Origin 머리글이 있으면 같은 출처여야 합니다('null' 출처도 거절).
  다른 웹사이트가 사용자의 브라우저로 몰래 보내는 요청을 막기 위함입니다.
- **외부 전송 없음**: 코드에 외부 호스트로 나가는 호출이 없습니다. 화면은 외부 CDN·글꼴을 쓰지 않습니다(CSP `default-src 'self'`).
  음성 읽기는 이 컴퓨터 안의 한국어 음성만 씁니다. 없으면 버튼을 숨기고 까닭을 알려 줍니다.
  입력칸은 맞춤법 검사를 끕니다(`spellcheck="false"`). 브라우저의 온라인 맞춤법 검사(예: Chrome '향상된 맞춤법 검사')가
  켜져 있으면 받는 사람·계좌번호·조력자 글이 브라우저 회사 서버로 가기 때문입니다.
- **저장**: 저장 폴더의 JSON 파일(동의·조력자·거래·결정·알림 기록)에만 둡니다. 쓰기는 임시 파일 뒤 교체(원자적)입니다.
  폴더에는 내용 없는 잠금 파일(`.sp-store.lock`, `serve.lock`: 켜져 있는 동안 화면 주소만 적음)도 생깁니다.
- **최소 수집**: 조력자 연락처는 가려서 저장합니다(전화 `010-****-5678`, 메일 `ab***@…`). 번호는 어떤 구분 기호로 나눠 적어도
  (`010ㆍ1234ㆍ5678`, `010/1234/5678` 등) 숫자가 7개 이상이면 가립니다. 조력자 메시지에는 금액·상대를 넣지 않습니다.
- **올린 파일**: 5MB까지. 크기는 본문을 받기 전(Content-Length)과 받는 동안(실제 바이트 수) 두 번 확인합니다.
  파일은 메모리에서만 읽고 시스템 임시 폴더에 쓰지 않습니다. 읽는 사이 지우기·동의 끄기가 먼저 끝나면 저장하지 않습니다.
- **명령행 보고서**: `analyze --out`이 쓰는 보고서 파일에는 받는 곳·금액·시각이 들어 있습니다. 저장 폴더 밖의 파일이라
  `wipe`·⑦ 지우기가 지우지 않으니, 필요 없으면 직접 지워 주세요.
- **즉시 철회**: 동의를 끄면 메모리의 분석 결과도 바로 버립니다. ⑦ 모두 지우기는 거래 기록부터 지우고,
  지우지 못한 파일이 있으면 그 목록을 한국어로 알려 줍니다.
- **알림은 기록만**: 조력자 알림은 이 컴퓨터에 적어 두기만 합니다. 문자·메일·앱 알림 발송 기능은 없습니다.

## 7. 한계

- 합성 데이터로만 성능을 쟀습니다. 실제 착취 피해 거래로 검증하지 않았습니다.
  룰 기준에 못 미치게 줄인 경계 변형에서는 결합 방식의 탐지율이 주의 이상 73.3%, 고위험 63.3%로 내려갔고,
  특정 계좌 송금 급증은 60사례 중 4사례만 잡았습니다(seed 1~20. 룰 보완에 쓰지 않은 seed 21~40에서는 74.3%, 63.0%, 5사례, 5장).
- 룰 기준은 seed 1~20 평가를 보며 보완했습니다. 룰 보완에 쓰지 않은 seed 21~40에서는 시나리오 없는 대조군의 알림이 더 많았습니다
  (결합 방식 1인당 월평균 알림 0.18 → 0.23건, 고위험 0.03 → 0.12건, 5장).
- 금융 마이데이터·은행 API와 연결하지 않았고 스마트폰 앱이 아닙니다. 거래는 합성 데이터나 올린 CSV로만 들어옵니다.
- 카드 문장은 발달장애 당사자 감수를 거치지 않았습니다(자동 규칙 검사만).
- 실제 은행·카드사 파일 양식으로 시험하지 않았습니다. 거래 종류(이체·카드·소액결제 등)는 글자로 추정하며 틀릴 수 있습니다.
  날짜만 있고 시각이 없는 파일은 모든 거래를 낮 12시로 두므로 심야 판단이 맞지 않습니다.
- 이력이 짧으면(평소 기준 7일 미만) AI 이상 점수는 0이고 룰의 하한 기준만 씁니다.
- 특정 계좌 송금 급증 룰은 오탐을 줄이려고 조건을 더했습니다: 고위험은 7일 합계 30만 원 이상일 때만, "배율만으로 고위험"은 2건 이상일 때만.
  이력 시작 뒤 30일 안에 처음 보인 상대는 새 상대인지 알 수 없어(예: 1개월치 파일의 늘 보내던 가족) 금액 경로로만, "확인해요"까지만 알립니다.
  새 가게 고액 결제·다회선 통신요금 룰도 같습니다: 이력 첫 30일 안에 처음 보인 가게·회선은 "처음"이라고 말하지 않고 "확인해요"까지만 알립니다
  (1개월치 파일의 치과·안경점 결제, 휴대폰·인터넷·태블릿 요금이 조력자 알림이 되던 문제). 이런 근거는 AI 점수가 높아도 "꼭 확인해요"로 올리지 않습니다.
  그래서 1개월치 파일 안에서 시작된 착취 송금·결제·명의도용 회선은 이 룰들로는 "꼭 확인해요"가 되지 않습니다(심야 반복 이체·소액결제 급증 룰은 그대로).
  합성 데이터의 송금 급증 시나리오에서는 첫 알림이 늦어졌습니다(결합 방식 첫 알림 순번 평균 1.65 → 2.45번째,
  이전 값은 SPEC.md §5 [변경 r1] 기록). 자세한 이유는 SPEC.md §5.
- 실제 송금 앱과 연결되지 않은 연습 화면입니다. 알림 발송·상담기관 연계는 제안(기록)까지만 합니다.
- 한 사람이 한 컴퓨터에서 쓰는 프로토타입입니다. 같은 저장 폴더에는 `serve`가 하나만 뜨고(두 번째 실행은 켜져 있는 주소를 알려 줌),
  저장소는 프로세스 사이 파일 잠금으로 기록을 줄 세웁니다. 네트워크 드라이브처럼 파일 잠금을 지원하지 않는 폴더는 확인하지 않았습니다.

## 10. 제출·배포용 압축 파일 만들기

폴더를 통째로 압축하면 `.venv`(수백 MB, 만든 컴퓨터의 Python 경로가 박혀 있음)가 따라가 다른 컴퓨터에서 실행이 실패합니다.
아래 명령으로 만드세요.

```bash
python packaging/make_release_zip.py      # → dist/SafePause-0.1.0-src.zip
```

- 넣을 파일은 허용 목록으로 고릅니다: `safepause/`, `tests/`, `docs/`, `sample_data/`, `packaging/`, `.github/`와
  README·SPEC·requirements·pyproject·실행 스크립트·Dockerfile·`.gitattributes`·`.gitignore`. 그 밖의 파일은 넣지 않습니다.
- 허용한 폴더 안에서도 `.venv`, `build`, `dist`, `*.egg-info`, `.pytest_cache`, `__pycache__`, `.git`과, 개인 데이터가 들 수 있는 파일
  (저장 파일 `consent/helpers/transactions/decisions/notices.json`, `analyze --out` 보고서 `file_eval_*`, 임시·잠금 파일,
  `sample_data` 밖의 `*.csv`)을 뺍니다. 끝에 zip을 다시 열어 이런 이름이 있으면 실패로 알립니다.
- `.bat`는 CRLF, `.sh`는 LF로 맞춰 넣고, 끝에 zip 안의 줄바꿈을 다시 세어 보여 줍니다.
  (`.bat`가 LF로 바뀌면 cmd.exe가 줄을 잘못 읽어 실행되지 않습니다. 저장소에는 `.gitattributes`로 줄바꿈을 고정했습니다.)

### 제출할 때: 실행파일 전달 방법

- Gmail 등 여러 메일 서비스는 보안 때문에 **.exe 파일 첨부를 막습니다(zip 안에 넣어도 막힐 수 있음).** `SafePause.exe`(약 65MB)는 첨부 용량 한도(Gmail 25MB)도 넘습니다.
- 그래서 `SafePause.exe`와 소스 zip은 **구글 드라이브·GitHub Releases 같은 다운로드 링크**로 전달하고, 메일 본문에 링크를 적습니다. 링크는 '링크가 있는 모든 사용자 보기'처럼 로그인 없이 받을 수 있게 설정해야 합니다.
- 받은 쪽이 파일이 같은지 확인할 수 있도록 SHA-256 값을 함께 적어 두면 좋습니다(Windows: `certutil -hashfile SafePause.exe SHA256`).
